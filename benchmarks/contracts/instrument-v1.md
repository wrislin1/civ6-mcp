## Predicate vocabulary (predicate schema 1.0.0)

Rubric level predicates, as the scorer source at the fingerprint above evaluates them:

- `successful_tool_call` — a step whose named tool returned a non-rejection result.
- `tile_state_equals` — a named field of a declared relevant tile, located by `(x, y)`, equals a value.
- `unit_at`, `unit_exists_final`, `unit_distance_decreased` — on a unit declared in `persistent_unit_ids`
  and present in canonical initial state; final disappearance evaluates false, never aborts.
- `all`, `any` — composites; `always` — unconditional.
- Objective progress predicates additionally use `state_changed_to` / `final_state_equals`
  (delta semantics: a mutation is "useful" only if it itself flips a progress sub-predicate from false to
  true), `success` and `domain_rejection` (a result prefixed `Error:` or `ERR:` or containing `|BLOCKED`).

## Authoring conventions established by the calibration campaigns

- The prompt is objective-blind and generic; it never names a task, tile, unit, civ, or rubric
  (pinned by `tests/arena/test_benchmark_contract.py`).
- Every level 4 predicate is false in the frozen starting state (asserted by the position's test module).
- Level 4 scores the outcome on the task tile (the named improvement present and intact), never a route to it
  (v2's "feature absent" predicate under-scored a real quarry; corrected in position v2 / campaign v3).
- Progress predicates equal completion predicates; conditions true at entry ("builder on target") are not
  progress predicates, because under delta semantics they can only flip by leaving and returning.
- Relevant tiles and persistent/consumable unit ids are declared; each task is legality-probed live through
  the standard arm's own tools before capture; twelve production-path deploy/reload cycles must reproduce the
  canonical digest; the crash-recovery menu path must also reach it.
- A positive control may start each builder on its target so each task is one call. A decision-quality
  position must not: the v1–v3 evidence shows farm-in-place attractors, decoy tiles and the 8-step budget
  all cap the effect once navigation is required.

## Compatibility rules

- Evidence stamped with this scorer fingerprint and these schema versions is comparable under this contract.
- A semantic scorer change bumps the affected version, recomputes the fingerprint, and forces a fresh campaign
  lock; evidence under the old fingerprint is not retained in the new campaign (v1 → v2 is the precedent).
- A rubric or prompt edit is a new position version with complete re-validation; it never rescales evidence.
- The 4/12 effect threshold is justified only for rubrics whose maximum is one complete task × 3 tasks = 12;
  a different rubric definition re-derives its threshold before freezing.
- Audit indices and tie-attribution values (`model_floor`, `same_progress`, `rubric_nondiscriminative`) are
  frozen before counting; the audit is a semantic read performed live and hash-bound to trial bytes.
